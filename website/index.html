Features

Everything PKI.
One sidebar.

A complete certificate workbench, built natively into VS Code. No browser tabs, no copy-pasting into sketchy websites, no command-line archaeology.

Inspect

Decode anything. Instantly.

Paste PEM, open a file, use the active editor or point at a live server. Certificate Utility classifies certificates, bundles, CSRs, private keys, PKCS#7, PKCS#12 and JKS — then decodes every detail.

  • Subject, issuer, SANs, serial, fingerprints and public-key metadata
  • Key usage, EKU, authority information and signature algorithm
  • AKI/SKI, CRL distribution points, policies, name constraints, path length and SCT presence

Validate with confidence

Validity windows, hostname matching, CA vs leaf usage, self-signed detection, and warnings for MD5/SHA-1 and short keys.

Chains that actually verify

Real cryptographic signature checks between every link — not just matching subject and issuer strings. Spot missing issuers, duplicate serials and broken links at a glance.

Remote TLS, natively

Fetch and inspect a server’s full certificate chain over a native TLS connection — no OpenSSL required. Prefer s_client? It’s supported when available.

Revocation checks

Check status online via CRL and OCSP, right from the Validate tab.

Expiry checker

Scan a folder recursively, sort by expiry, filter and export JSON, Markdown or CSV for CI and audits.

Remote watchlist

Monitor every host:port you care about and get a Markdown status report.

Generate

Keys, CSRs and certs.

Create RSA (2048/3072/4096), EC (P-256/P-384) and Ed25519 key pairs. Generate CSRs with subject and SANs, self-signed or CA certificates with custom validity, and build PKCS#12 (PFX) bundles natively.

Convert & keystore

Format wrangling, solved.

Inspect PKCS#7 and PKCS#12 natively. Generate ready-to-run OpenSSL and Java keytool commands for PEM ↔ DER, PFX export, and JKS to PKCS#12 — with explicit paths, so nothing is guessed.

Viewer & diff

Double-click to open.

A read-only Certificate Viewer opens for .pem, .crt, .cer, .der, .p7b and friends. Compare two certificates side by side in a diff editor.

Key match

Does this key fit?

Verify a private key corresponds to a certificate by signing and verifying a nonce. No key material ever leaves your machine.

Built in

Documentation & glossary, included.

A searchable reference for every tool plus a glossary of PKI terms — X.509, PEM, DER, PKCS#12, CSR, SAN, AKI/SKI, CRL, OCSP, fingerprints and more. Status bar expiry for the active file and right-click inspect in the Explorer complete the picture.

Privacy

Your keys stay yours.

Parsing, generation and key matching run inside the VS Code extension host. Certificate contents, private keys and scan results are never uploaded, and there is no telemetry.

100% local

Everything happens on your machine or your remote workspace.

Network on request

Remote inspection, CRL/OCSP and the watchlist only connect to endpoints you enter or configure.

Untrusted workspaces

Supported, so you can safely look at certificates in code you haven’t reviewed.

FAQ

Good questions.

Is it really free?

Yes. Certificate Utility is open source under the MIT license.

Do I need OpenSSL installed?

No. Parsing, generation, chain verification, revocation checks and remote TLS inspection run natively. OpenSSL is only used as a fallback for rare PKCS#7/PKCS#12 variants, trust verification and optional s_client inspection.

Does it upload my certificates or private keys?

Never. Everything is processed in the extension host. The only network traffic is what you explicitly request: remote TLS inspection, CRL/OCSP lookups and watchlist checks.

Can I use it in CI or audits?

The expiry checker exports JSON, Markdown and CSV reports, and the remote watchlist produces a Markdown status report, so results are easy to keep and share.

Does it work with remote and untrusted workspaces?

It works in local and remote (SSH, containers, WSL) workspaces and in untrusted workspaces. Virtual file systems aren’t supported because certificate files and external tools need a real file system.

Where do I report a bug or request a feature?

Open an issue on GitHub.
